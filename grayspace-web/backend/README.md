# GraySpace Web Backend

FastAPI backend for the GraySpace Management Web Application.

## Features

- **Phase 1: Core Visualization** - REST API endpoints for network topology (routers, links, ISPs)
- **Phase 2: Real-time State** - WebSocket for live BGP peer state updates from Prometheus
- **Phase 5: Container Management** - Proxmox API integration for start/stop/restart operations

## Setup

1. Install dependencies:
```bash
pip install -r requirements.txt
```

2. Configure environment:
```bash
cp .env.example .env
# Edit .env with your deployment settings
```

3. Run the application:
```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

## API Documentation

Once running, access interactive API docs at:
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

## Key Configuration

### Environment ID (CRITICAL)

The `ENVIRONMENT_ID` must match your Terraform deployment's `TF_VAR_environment_id`. This ensures:
- Only containers with matching tags are visible/manageable
- Multi-developer deployments don't interfere with each other
- Complete isolation between dev1, dev2, production, etc.

### Data Sources

- **terraform.tfvars.json**: Network topology (routers, links, ISPs, locations), generated by `task parse`
- **Prometheus**: Real-time BGP/OSPF state metrics
- **Proxmox**: Container lifecycle management

## Architecture

```
main.py                         # FastAPI application
├── routers/
│   ├── topology.py            # Network topology endpoints
│   ├── websocket.py           # WebSocket for real-time updates
│   └── containers.py          # Container management endpoints
├── services/
│   ├── topology_service.py    # Topology from tfvars + Proxmox state
│   ├── prometheus_client.py   # Prometheus metrics queries
│   ├── proxmox_client.py      # Proxmox API operations
│   └── websocket_manager.py   # WebSocket connection manager
├── tasks/
│   └── state_monitor.py       # Background BGP state polling
└── config.py                   # Configuration management
```

## Deployment Isolation

The application implements strict deployment scoping:

1. **Container Discovery**: Proxmox queries filter by `environment_id` tag
2. **Network Topology**: Read from the deployment's `terraform.tfvars.json`
3. **Metrics**: Prometheus instance specific to deployment
4. **Operations**: All start/stop/restart operations verify tag match

This matches the pattern in `/workspaces/scripts/manual_cleanup.py` where containers are filtered by tag.

## Tests

```bash
cd grayspace-web/backend
pip install -r requirements-dev.txt     # or: task backend:venv
python -m unittest discover -s tests -t .
```

The tests fake Proxmox, Prometheus, SSH and the tfvars, so they need no deployment. Slice jobs run
end to end against fake `terraform` and `ansible-playbook` executables (`tests/fake_tools.py`) and
the real DNS code against temporary directories (`tests/fake_hosts.py`). They need the pinned
`requirements.txt`; `pydantic==2.9.0` has no build for Python 3.14, so use Python 3.13 or earlier
(the deployed container runs Ubuntu 22.04's Python 3.10).

## Auth

`GRAYSPACE_API_TOKEN` is required as a bearer token on the Terrain API, on every write route and
on the console and desktop websockets (`services/auth.py`); unset, those return 503. Browsers may
call the API only from `GRAYSPACE_CORS_ORIGINS`.

## Slices

`services/slices/` holds the slice code the API and `slicectl.py` (the CLI behind `task slice:*`)
share: the spec is resolved against the deployed base by `plan.py`, stored by `store.py`, rendered
for Terraform and Ansible by `render.py`, and built by the jobs in `stages.py`, which `runner.py`
runs one at a time under the node lock. See [docs/slices.md](../../docs/slices.md).

## Terrain API contract

`openapi/grayspace-v1.json` (at the repository root) is the contract GHOSTS builds against. It
covers only the Terrain API routes listed in `contract.py`, not the routes private to the web UI.
Next to it, `grayspace-slice-v1.json` is the JSON Schema of the slice spec and
`grayspace-events-v1.json` that of the `/api/v1/events` websocket's messages. After changing a
contract route or model, regenerate them:

```bash
cd grayspace-web/backend
python contract.py
```

`tests/test_contract.py` fails if the committed spec is out of date.
